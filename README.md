# СКВОЗНЯКИ

Сайт школьного ток-шоу НИШ IB (Астана). Ученики оставляют три вида заявок: «Хочу в выпуск», «Идея для выпуска» и «Новость школы». Команда разбирает их в закрытой админке. На сайте появляется только то, что ведущие одобрили вручную.

Стек: Next.js 16 (App Router) · TypeScript · Tailwind CSS 4 · Motion · Supabase · Vercel.

## Быстрый старт (демо-режим, без базы)

```bash
npm install
npm run dev
```

Откройте http://localhost:3000. Без переменных Supabase сайт работает на примерных данных в памяти сервера. Админка: http://localhost:3000/admin, пароль `efir` (только в dev; в production задайте `DEMO_ADMIN_PASSWORD`). Данные демо-режима пропадают при перезапуске.

## Как переименовать шоу

Всё в одном файле: `src/config/site.ts` → `name`, `nameLatin`, `nameLines` (как название делится на две строки в hero). Там же ведущие, фото и соцсети.

## Соцсети

`src/config/site.ts` → `handle` и `social` (Instagram, TikTok, YouTube @skvoznaki). Иконки и ссылки подхватываются везде сами: шапка, раздел «Выпуски», экран после отправки заявки, футер, QR-плакат и разметка для поисковиков (`sameAs`).

Фото ведущих: положите `public/hosts/yerkin.jpg` и т. д. и укажите `photo: "/hosts/yerkin.jpg"`. Пока фото нет, карточка рисует цветную монограмму.

Все тексты на трёх языках лежат в `src/i18n/dictionary.ts`. Русский — эталон: если в казахском или английском не хватает ключа, TypeScript не даст собрать проект.

## Вентилятор: файлы бренда

Вентилятор — символ шоу: логотип в шапке, иконка вкладки, hero, экран успеха, центр QR-кода. Отдельные файлы лежат в `public/brand/`:

| Файл | Для чего |
|---|---|
| `fan.svg` | Логотип в векторе: плакаты, мерч, монтаж |
| `fan-animated.svg` | Крутящийся логотип (заставки, сайт, презентации) |
| `fan-1024.png` | Прозрачный PNG для монтажа видео |
| `avatar-1080.png` | Аватарка Instagram/TikTok/Telegram: «СКВОЗНЯКИ · @SKVOZNAKI», текст влезает в круглую обрезку |

Форма лопасти в коде — `BLADE_PATH` в `src/components/site/fan-mark.tsx`.

## Админка

Адрес: **`/admin`** (на GitHub Pages: `https://diawx-6669.github.io/ventilatorrr/admin/`).

Что там есть:

| Вкладка | Что делает |
|---|---|
| Хотят в выпуск / Идеи / Новости | Все заявки, счётчик новых на вкладке, статусы, заметки команды, публикация идей и новостей на сайт, удаление спама, поиск, выгрузка в CSV (Excel), кнопка «Обновить» |
| Выпуски и видео | Вставь ссылку на YouTube (в т. ч. Shorts), Instagram (пост/reels) или TikTok: админка сразу узнаёт платформу и показывает превью. Номер и дата подставляются сами. Выпуск появляется на сайте сразу |
| Команда | Список людей с доступом. Владелец добавляет человека по email и получает ссылку-приглашение (копировать / Telegram / письмом), сбрасывает пароль, убирает из команды. Любой может сменить свой пароль |

### Как устроен вход

Писем никто не шлёт, SMTP настраивать не нужно.

1. Владелец во вкладке «Команда» вводит email → появляется одноразовый код и ссылка `…/admin/?email=…&invite=КОД` (действует 7 дней).
2. Человек открывает ссылку, придумывает пароль (от 8 символов) и сразу попадает в админку. Дальше входит по email и паролю, сессия живёт 30 дней.
3. Забыл пароль → владелец жмёт «Сбросить пароль» и отправляет новую ссылку.

Защита: пароли хранятся как bcrypt, токены сессий как SHA-256, после 8 неверных попыток вход по этому email закрывается на 15 минут. Приглашать и удалять людей может только владелец (`is_owner`).

Если владелец потерял доступ: Supabase → SQL Editor:
```sql
update public.admins set invite_hash = public._sha('NEWCODE1'), invite_expires_at = now() + interval '7 days', password_hash = null
where email = 'yerkin.ye@nisa.edu.kz';
```
и откройте `/admin/?email=yerkin.ye@nisa.edu.kz&invite=NEWCODE1`.

## Supabase

Проект **skvoznyaki** (регион Frankfurt) уже создан, миграции применены, владелец админки `yerkin.ye@nisa.edu.kz`. Для нового проекта с нуля:

1. Создайте проект на https://supabase.com.
2. **SQL Editor** → по очереди вставьте и выполните `supabase/migrations/0001_init.sql` и `0002_team_accounts.sql`.
3. Добавьте владельца (код придумайте сами, 8 букв/цифр):
   ```sql
   insert into public.admins (email, is_owner, invite_hash, invite_expires_at)
   values ('owner@example.com', true, public._sha('ABCD2345'), now() + interval '7 days');
   ```
   Затем откройте `/admin/?email=owner@example.com&invite=ABCD2345`.
4. **Project Settings → API**: URL и `anon` key → в `.github/workflows/pages.yml` (для Pages) или в переменные окружения (для Vercel).

### Кто что может

| Роль | Права |
|---|---|
| Аноним (сайт) | `INSERT` в три таблицы заявок, только в «ученические» колонки (статус, публикацию и голоса подделать нельзя). `SELECT` только одобренных и опубликованных строк и только публичных колонок. Голос через `vote_idea` (один на идею с браузера). Загрузка фото новости только в формате `ГГГГ-ММ/uuid.jpg` |
| Команда | Только через функции `admin_*`: каждая проверяет токен сессии. Напрямую к таблицам доступа нет |
| Сервер (`service_role`, только Vercel) | Вставка заявок, `cast_vote`, `hit_rate_limit` |

`anon` key в workflow — это нормально: он публичный по замыслу Supabase и даёт ровно то, что разрешено выше.

Антиспам на уровне базы: триггер не даёт отправить больше 20 заявок в час с одного IP (и 300 в час всего, если IP неизвестен). Плюс honeypot и тайм-ловушка в браузере.

## Переменные окружения (Vercel / локально)

Скопируйте `.env.example` в `.env.local` или добавьте в Vercel → Settings → Environment Variables:

| Переменная | Зачем |
|---|---|
| `NEXT_PUBLIC_SITE_URL` | Адрес сайта: QR-плакат и превью ссылок |
| `NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_ANON_KEY` | Включают Supabase вместо демо-режима |
| `SUPABASE_SERVICE_ROLE_KEY` | Голосование и общий rate-limit на сервере. Только на сервере |
| `HASH_SALT` | Случайная строка (`openssl rand -hex 32`): соль для хешей IP и устройств |
| `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID` | Необязательно, только Vercel: уведомление в чат команды о каждой заявке |
| `DEMO_ADMIN_PASSWORD` | Только для демо-режима без Supabase |

**Telegram-бот:** создайте бота у @BotFather и добавьте его в чат команды. Затем напишите в чат любое сообщение, откройте `https://api.telegram.org/bot<TOKEN>/getUpdates` и возьмите `chat.id` (для групп он отрицательный).

## Хостинг

### GitHub Pages (основной)

`https://diawx-6669.github.io/ventilatorrr/` собирает `.github/workflows/pages.yml` при каждом пуше в `main`. Включить один раз: **Settings → Pages → Source: GitHub Actions**.

Сервера нет, поэтому браузер ходит в Supabase сам: формы, голосование, админка и свежие данные на главной работают. Опубликованное в админке видно на сайте сразу, без пересборки. Без ключей Supabase в workflow сайт превращается в витрину (формы показывают «Приём заявок скоро откроется»).

Не работает на Pages только Telegram-уведомление о новой заявке (нужен сервер). Заявки видно в админке, счётчик новых на вкладках.

### Vercel (по желанию)

Импортируйте репозиторий, добавьте переменные из таблицы выше, Deploy. Формы и голоса пойдут через API-роуты (с Telegram-уведомлениями), админка та же.

Обе версии собираются из одного кода: `npm run build` (сервер) и `npm run build:pages` (статика в `./out`).

## Защита и приватность

- **Honeypot**: скрытое поле, которое заполняют только боты; такие заявки молча «принимаются» и не сохраняются.
- **Time-trap**: заявка, отправленная быстрее 2,5 с после открытия формы, считается ботом.
- **Rate-limit**: на Vercel не больше 5 заявок в час с одного IP, на Pages триггер в базе (20 в час с IP). IP хранится только как хеш, сутки.
- **zod на клиенте и сервере**: одна и та же схема (`src/lib/schemas.ts`).
- **Фото**: перед отправкой перекодируются в браузере через canvas, поэтому из них удаляются геолокация и данные камеры. Для анонимной новости это важно: GPS в EXIF может выдать автора. На сервере проверяется реальная сигнатура файла, а не только заявленный тип.
- **Минимум данных**: без фамилии, телефона и ИИН. Анонимная новость не хранит ни имени, ни IP.
- **CSV-экспорт** с BOM (Excel правильно открывает кириллицу и казахские буквы) и защитой от формул (CSV injection).
- **Голоса**: один на идею с устройства (на Vercel httpOnly-cookie, на Pages случайный id в браузере; в базе только хеш). Ограничение по IP намеренно не используется: вся школа выходит в интернет через пару Wi-Fi-адресов. На Pages голос можно «накрутить», очистив данные браузера: для школьного голосования это приемлемо.

## Проверка качества

```bash
npm run build && npm start
node scripts/qa.mjs http://localhost:3000
```

`scripts/qa.mjs` (нужен Playwright с Chromium) делает две проверки:
1. Через DevTools-протокол спрашивает Chromium, **каким шрифтом на самом деле нарисованы** Ә Ғ Қ Ң Ө Ұ Ү Һ І, и падает, если хоть одна буква ушла в запасной шрифт.
2. Ищет горизонтальную прокрутку и вылезающие заголовки на всех страницах × 3 языка × ширины 320 / 375 / 1440.

### Шрифты

- **Science Gothic** (заголовки, оси ширины и веса) + **Onest** (текст), OFL.
- Отбор: Unbounded, Dela Gothic One, Russo One, Rubik Mono One и Wix Madefor не поддерживают казахские буквы, поэтому отбракованы. Science Gothic и Onest прошли проверку на всех 18 глифах.
- Подмножества вырезаны `pyftsubset` в `src/fonts` (~135 КБ на всё) и подключены через `next/font/local` (`src/app/fonts.ts`) с `unicode-range`: казахский файл грузится, только когда на странице есть казахские буквы.
- Заголовки сами подгоняют кегль под длину самого длинного слова (`src/lib/fit.ts`): казахские слова длиннее русских.

## Структура

```
src/
  app/(site)/[lang]/   публичный сайт: / (ru), /kk, /en; join, idea, news, qr
  app/(admin)/admin/   админка (статическая страница, работает и на Pages)
  components/admin/    backend.ts (Supabase-RPC или демо API), вкладки заявок, выпусков, команды
  app/api/             submit, vote, admin/* (admin/* только для демо-режима)
  components/site/     hero (вентилятор + ветер), ticker, doors, hosts, episodes, ideas…
  components/forms/    поля, движок отправки, экран успеха, сжатие фото
  lib/repo/            demo.ts (память) и supabase.ts за одним интерфейсом, общие запросы
  lib/direct.ts        «бэкенд» статического сайта: заявки, голоса, свежие данные из Supabase
  proxy.ts             языки
supabase/migrations/   SQL: таблицы, RLS, RPC, storage
```

Публичные страницы — ISR (`revalidate = 60`) на Vercel; на Pages главная после загрузки подтягивает свежие данные из Supabase.
